# Amendment 2026-10-19-04: arm isolation, and a third pilot start

Written before any score is seen; no attempt has been graded. CONFIG.md §3 says the CLI's "only web path is the arm's MCP tools". That was not true of the code both pilots ran on. Under amendment 02 §6 this is the harness bug that forces a rerun, logged here.

## Finding

Codex 0.162.1, signed in with ChatGPT, turns on features by default that give the model more than the arm's two tools:

- `apps` adds a second MCP catalog, `codex_apps`. With it on, Codex's own log (`RUST_LOG=info`) shows `server_kind="codex_apps" tool_count=180` next to the arm's `server_kind="configured" tool_count=2`. Among those 180 tools is `search_service.web_run`, ChatGPT's own web search, outside both backends, the blocklist and the trace.
- The shell tools could read any file on this machine, since the read-only sandbox allows reads from `/`. That reaches this repo's `tasks/` and `.env`, though not the network.
- Other features added image generation, browser and computer use, plugin installs, sub-agents and the owner's personal skills folder to the arm's context.

An audit of all 49 Codex event logs (both pilots, the smoke tests and the calibration runs) found:

- calls to `codex_apps` / `search_service.web_run` in 21 of the first pilot's 38 attempts and in A1-008 exa attempt 2 of the second pilot, all of it in pilot attempts;
- no shell or code command in any run, so no file was read.

## Fixes

- Each attempt's `config.toml` turns these features off (`FEATURES_OFF` in `harness/codex_arm.py`): `apps`, `plugins`, `remote_plugin`, `plugin_sharing`, `tool_suggest`, `skill_search`, `skill_mcp_dependency_install`, `browser_use`, `browser_use_external`, `browser_use_full_cdp_access`, `browser_annotation_api`, `in_app_browser`, `computer_use`, `image_generation`, `view_image`, `shell_tool`, `unified_exec`, `unified_exec_tty`, `shell_snapshot`, `multi_agent`, `goals`, `hooks`, `sleep_tool`.
- `code_mode_host` stays on: in this version the MCP tools run through code mode, and with it off every tool call fails ("Code Mode is unavailable because code-mode host is disabled").
- The Codex process runs with `HOME` set to the attempt's empty workdir, so nothing from the owner's home directory reaches the arm.
- Every attempt records proof of isolation. Codex runs with `RUST_LOG=info`, and the record keeps every MCP catalog Codex logged it built (`mcp_catalogs`) and every event item other than the model's own messages and calls to the arm's `search` server (`foreign_items`). If an attempt shows any catalog besides `configured` with 2 tools, or any foreign item, the runner stops, and that attempt is not scored. The smoke test fails on the same conditions.
- Checked 2026-10-19 under the new config:
  - Codex built only the arm's catalog (`configured`, 2 tools).
  - The smoke test passed on both arms: one search each through the MCP server, the throwaway question answered, no foreign item; the sandbox had no network.
  - Asked twice to read the first line of `/etc/hosts` with any capability other than search, the arm replied "CANNOT READ FILES" both times, with no foreign item.
- Base tokens, superseding amendment 03 §5: under this config a request with no tool call carried 9,289 to 9,292 input tokens on both arms (two runs per arm), so the ceiling estimate's base is now 10,000 tokens.
