# Amendment 2026-10-19-02: backends, prices, grading and reporting for the main run

Written after the freeze tag and before any main-run attempt; no score has been seen. CONFIG.md and PROTOCOL.md stay as frozen; each section says what it adds to or rewords.

## 1. Backend requests and responses

Read 2026-10-19 from the vendors' docs, and checked on live responses the same day. Both arms expose the same two tools, `search` and `fetch`, with identical names, descriptions and schemas (`harness/mcp_search.py`); the request code is `harness/arms.py`.

**Exa** (auth header `x-api-key`)
- Search: `POST https://api.exa.ai/search`, body `{"query": <the model's query>, "numResults": 10, "contents": {"text": {"maxCharacters": 400}}}`. `type` is not sent, so Exa uses its default, `auto` ("Defaults to `auto`", https://exa.ai/docs/reference/search); the live cost breakdown labels it `neural`. Result text is each result's `text`, which Exa cuts to 400 characters on its side ("Maximum character limit for the full page text"). The model also gets `title`, `url` and `publishedDate` (as `date`). Live response: top level `requestId`, `results`, `costDollars`, `searchTime`, `resolvedSearchType` (deprecated; empty); per result `id`, `title`, `url`, `publishedDate`, `text`, `image`.
- Fetch: `POST https://api.exa.ai/contents`, body `{"urls": [<url>], "text": {"maxCharacters": 8000}}`, every other option at its default (https://exa.ai/docs/reference/get-contents): `maxAgeHours` unset (cached content when available, otherwise fetched live), `livecrawlTimeout` 10000 ms, `subpages` 0. The model gets `title`, `url` and `text`, cut to 8,000 characters on Exa's side. The per-URL `statuses` entry (`success` or `error`, `source` `cached` or `crawled`, `error`) goes to the trace.
- Because Exa cuts on its side, a trace records Exa's returned length, which stops at 400 or 8,000 characters; a page's full length is not observable. An Exa fetch counts as truncated when it returns exactly 8,000 characters.

**DeepSeek** (auth header `Authorization: Bearer`)
- Search: `POST https://api.deepseek.com/v1/tools/search`, body `{"query": <the model's query, cut to 128 characters>, "count": 10}`. `need_content` (default `false`), `ori_question` (none) and `localization` (default `""`) are not sent (https://api-docs.deepseek.com/api/search, https://api-docs.deepseek.com/guides/search). Result text is each result's `summary` ("A long summary related to the query, typically 600 to 800 characters, intended to be read by a model"), cut to 400 characters here. The model also gets `title`, `url` and `date`. Live response: top level `results`; per result `rerank_score`, `title`, `url`, `snippet`, `summary`, `content` (empty, as `need_content` is false), `site_name`, `site_icon`, `date`, `authority`. The trace records each summary's full length and the cut.
- Fetch: `POST https://api.deepseek.com/v1/tools/fetch`, body `{"url": <url>}` (https://api-docs.deepseek.com/api/fetch). The model gets `title` and `content` (Markdown), cut to 8,000 characters here; the trace records the full length. A page DeepSeek cannot fetch comes back as an HTTP error with an `error` object (seen live: HTTP 404 on a page Exa fetched), which the model receives as that call's error output.
- Rate limits: Search 100 QPS and Fetch 25 QPS per account, plus a per-domain Fetch limit; over them, HTTP 429 (https://api-docs.deepseek.com/guides/search).

## 3. Grading

Adds to PROTOCOL §4 and CONFIG §3 for the study run (`harness/grade.py`, `make grade`, re-runnable); `tests/grade_guard.py` pins the rules below on fixed unit cases.

- The answer is the last `Exact Answer:` line (PROTOCOL §4). With none, the attempt is `NO_ANSWER_LINE`: incorrect, no judge call.
- Normalization, applied alike to answer and gold: Unicode NFKC; case folded; inner whitespace collapsed; quotes, brackets and markdown emphasis stripped from both ends, sentence punctuation from the end; thousands separators dropped (a comma between digits followed by exactly three digits). A whole string that is a number (optional sign, decimals, optional %) becomes its canonical value, without trailing zeros. A whole string that is a date in one of the forms `2026-01-05`, `2026-01`, `January 5, 2026`, `Jan. 5, 2026`, `5 January 2026`, `5th Jan 2026`, `January 2026` becomes ISO (`2026-01-05`, `2026-01`); slash dates such as `01/05/2026` and invalid dates stay text. Anything else that splits on semicolons, commas (not between digits) or " and " / " & " into two or more items becomes a list of normalized items, compared as a multiset in any order. Otherwise the cleaned text is compared.
- Exact match after normalization → correct, without judges.
- Otherwise both judges grade the answer, blinded (question, gold and answer only) and independent: `jev-1.13.0` with `harness/prompts/judge_jev.json` (sha256 `142c17a748f5b9198e621bb63c8bbd22abe33cabf8e6302e52fe04c513bc8f23`) and `perplexity/sonar` with `harness/prompts/judge_perplexity.txt` (sha256 `e12c4a5844acd4a73f6406bcb3c51cad3033ca7fa640d9b42b2d9a87a01fb376`). If they agree, that is the verdict. If they disagree, the owner adjudicates: the attempt waits in `results/owner_queue.jsonl`, and the owner's decision is logged in `results/owner_decisions.jsonl` and carried into `results/grades.jsonl`.
- Calibration, replacing PROTOCOL §4's 30 answers: the owner grades the 40 staged answers (§6). Agreement of each judge with the owner, and of the two judges with each other, is reported.

## 7. Tagging

Adds to PROTOCOL §8 and to CONFIG §6's per-type breakdown. `TAG_MODEL` gives every frozen task one tag from each taxonomy, working from the question and gold alone. It never sees arm outputs, grades or scores. Its rubric is committed before any tagging run.

Type, the taxonomy of PROTOCOL §1's `TYPE_QUOTA`, defined by §4; one tag per task, the first that applies in this order:
- `lists`: the answer is an exhaustive set, every X that meets condition Y.
- `exceptions`: the answer turns on a qualifier below the headline, such as an exception clause, a footnote condition, a unit or an effective-date condition.
- `tables-footnotes`: the answer sits in a table, chart, appendix or footnote rather than in running text.
- `distributed`: answering takes facts from two or more independent sources combined.
- `facts`: none of the above; the answer is one fact a single source states, however many hops reach it.

Answer form, the forms of PROTOCOL §4's **Answer**:
- `number`: a quantity, with or without a unit.
- `date`: a calendar date, month or year.
- `short string`: a name, title or other short text.
- `list`: two or more items.
