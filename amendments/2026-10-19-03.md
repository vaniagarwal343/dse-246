# Amendment 2026-10-19-03: review fixes, and a restarted pilot

Written before any score is seen; no attempt has been graded. Reason: the owner's hostile review of the run setup (2026-10-19) found five problems in the code the first pilot ran on. This amendment fixes them, sets that pilot's attempts aside and restarts it. Where a fix changes CONFIG.md §3 or amendment 2026-10-19-02, the section is named.

## Findings and fixes

1. **Search text differed in kind between the arms.** Exa's result text was page text (`contents.text`, the first 400 characters), while DeepSeek's was its query-focused `summary`. Fix: Exa now returns `contents.highlights`, its query-focused excerpts, requested with `maxCharacters` 400, joined, and cut to 400 characters here; DeepSeek keeps `summary`, cut to 400. A live check on 2026-10-19 found highlights cost the same, $0.007 per search, and that one result came back at 867 characters despite `maxCharacters` 400, so the cut on our side stays. Changes CONFIG §3 (Search) and amendment 02 §1 (Exa search).
2. **Timeouts were retried.** CONFIG §3 retried a timed-out attempt as an infrastructure failure, which gave a slow arm extra tries. Fix: a timeout (3,600 s) ends a completed attempt with no answer, scored `NO_ANSWER_LINE`. Retries, up to 3, are only for transport errors and CLI crashes. Changes CONFIG §3 (Attempts).
3. **Only DeepSeek capped query length.** DeepSeek's API cut queries at 128 characters, while Exa received the full query. Fix: both arms cut at 128 characters (`QUERY_CAP`), as the shared search tool's description already said, and the trace logs the query actually sent. Changes CONFIG §3 (Tools) and amendment 02 §1.
4. **Nothing kept an arm from the answer key.** Fix: a blocklist applied identically to both arms in `harness/mcp_search.py`. Search results whose URL is listed are dropped. A fetch of a listed URL is refused without a backend call, and the model sees only "This URL is not available.". The refused fetch still counts as a tool call. Every block is logged as `BLOCKED_KEY_DOMAIN` with its rule. The rules (`BLOCKLIST` in `harness/arms.py`):
   - any URL containing arXiv 2605.28721 (the LiveBrowseComp paper) or 2606.13120 (the EvoBrowseComp paper), on arxiv.org or any mirror;
   - any URL containing `livebrowsecomp`, `evobrowsecomp` or `evobrowcomp`, which covers the Hugging Face dataset pages (huggingface.co/datasets/Forival/LiveBrowseComp, huggingface.co/datasets/Krystalan/EvoBrowseComp), the LiveBrowseComp project page and its repo (github.com/LiveBrowsecomp/LiveBrowsecomp.github.io), and mirrors that slug either title;
   - the GitHub repo vaniagarwal343/lbc-30, including raw files, which hosts LiveBrowseComp records (encrypted) with their decryption script.
   A GitHub search on 2026-10-19 found no repo hosting EvoBrowseComp.
5. **The ceiling estimate's base came from one arm.** The base, 30,000 tokens, came from the Exa smoke run, read as two requests. Fix: measured on both arms, a request with no tool call carried 11,869 to 11,872 input tokens (two runs per arm, 2026-10-19), so the base is now 12,000 tokens. Changes CONFIG §3 (Input-token ceiling).

The CLI smoke test passed again on the fixed code on 2026-10-19 (`pipeline/smoke_report.md`): both arms searched through their MCP tools and answered the throwaway question, and the sandbox had no network.
